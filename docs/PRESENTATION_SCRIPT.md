# 标准智编 PPT 汇报文稿与目标效果

## 1. 项目定位

标准智编面向企业标准化团队，把研发技术要求、参考标准、专家意见和政策变化放到一条可追溯的协同链路中。项目以“AI 辅助生成，人机协同确认”为原则，优先解决标准草案编制效率低、评审意见分散和政策解读滞后的问题。

## 2. 模块汇报口径

### 模块一：AI 辅助标准草案生成与协同审查

工程师上传技术要求和参考标准模板后，系统先解析并结构化为统一 Markdown，再由 AI 按 GB/T 1.1 的章节规范完成字段映射和草案编排。系统生成可审阅的标准草案、编制说明和预研报告，并高亮研发输入映射的关键参数；确认后的版本可同步至飞书，供多人在线协同、评审和审批流转。

### 模块二：标准公告与组织追踪

模块二聚焦标准公告、关联标准和起草组织的统一追踪，帮助团队从分散的公开信息中快速识别与自身产品、技术路线相关的变化。系统以标准编号和来源链接作为主线，保留采集来源、更新时间和关联关系，为后续接入合规数据源和企业知识图谱预留接口。

### 模块三：政策收集与智能解读

模块三是“政策收集与智能解读”：系统聚合标准化相关政策，完成分类、重点提取和影响研判。AI 主要用于政策文本的语义分类、关键要求抽取和解读报告生成，并给出带原文依据的标准修订与合规建议，帮助团队快速形成行动结论。

## 3. AI 的作用与实现效果

| 能力 | AI 或自动化作用 | 演示中的实现效果 |
| --- | --- | --- |
| 技术要求转标准草案 | 识别输入中的范围、术语、性能指标、试验条件和待确认事项；按章节和模板字段生成候选内容。 | 选择内置 DOCX 或上传技术文件，结合参考模板生成标准草案、编制说明和预研报告。 |
| 模板化、可追溯生成 | 将输入和模板统一为 Markdown，结合模板章节、字段和约束完成映射。 | 记录来源、模板和关键参数映射，并高亮需要工程师确认的参数。 |
| 条款审核与协同 | 基于规则和 LLM 给出规范性、术语、引用与条件完整性问题的候选建议。 | 平台展示条款级问题和修订状态，确认后的草案可同步到飞书在线编辑、评论和审批。 |
| 政策智能解读 | 对政策文本做语义分类、关键要求抽取和影响研判。 | 输出“适用对象、核心变化、建议动作、风险提示”，并关联原文证据。 |

## 4. 黑客松演示闭环

```text
技术要求 / 参考标准模板
  -> 解析为统一 Markdown
  -> AI 按章节与字段映射生成草案
  -> 高亮关键参数并进行条款审阅
  -> 同步飞书在线协同
  -> 发起审批、处理意见、归档版本
```

## 5. 已实现效果与后续扩展

| 目标 | 黑客松演示效果 | 后续扩展方向 |
| --- | --- | --- |
| 技术要求转标准草案 | 选择内置 DOCX 或上传技术文件，结合参考模板生成三类可编辑文档，并标注待确认字段。 | 接入企业模板库、行业术语库与更完整的 GB/T 1.1 规则包。 |
| 模板化、可追溯生成 | 将输入和模板统一为 Markdown，记录来源、模板和关键参数映射，避免 AI 脱离原始技术要求补造内容。 | 持久化条款、字段溯源、模型版本和人工修订记录。 |
| 多人协同与审核 | 草案同步到飞书文档，在线编辑、评论并发起审批；平台展示条款级审核问题和修订状态。 | 通过 Yjs / ONLYOFFICE 或企业既有系统实现实时协同和双向版本回写。 |
| 政策与标准知识辅助 | 展示带来源依据的政策解读和标准检索结果，辅助发现修订与合规风险。 | 建立受控索引、Agent RAG、标准差异分析与引用有效性校验。 |

## 6. 演示与合规边界

- AI 生成的是候选草案、审核建议和政策解读草稿，不自动发布标准。
- 性能限值、引用文件、审批结论及政策解读均须由人工确认。
- 演示数据、公告采集、组织关联和部分审核结论属于 MVP 演示范围；生产环境需接入有授权的数据源和受控的企业流程。
