## 二、演示前置准备（务必先确认）

1. **启动服务**：`node serve-demo.mjs`（默认 5277 端口，被占用会自动向后顺延，看控制台输出的实际端口）。
2. **LLM 配置**：确认 `ds配置.json` 已配置（DeepSeek，`deepseek-v4-flash`），或设置环境变量 `STD_LLM_BASE_URL/STD_LLM_API_KEY/STD_LLM_MODEL`。页面右上角会显示「LLM 已启用 / 未配置」——未配置也能跑，但结构化提取降级为「页面显式键值」，不产生 AI 标签/结论（见 §五-2 疑难解释）。
3. **网络可达**：演示机需能访问 `std.samr.gov.cn`、`hbba.sacinfo.org.cn`、`org.sacinfo.org.cn:8088`（均为政府公开数据，无需登录）。
4. **邮件推送（可选，建议准备）**：如需演示「审批后推送邮箱」，需先启动 `../pdf-parser/server.mjs`（端口 4175，SMTP 凭据走 `.env.smtp.local`），并在「收件人管理」（页面右上角）配置白名单收件人。若邮件服务未启动，页面会显示「SMTP 未配置」，此时跳过推送环节即可，不影响其他功能演示。
5. **建议准备一张「数据口径提示卡」**：把 §五 的疑难解释做成小抄，评委问「这个数字哪来的 / 这个'演示'标记是什么 / 每日采集预警和采集预警什么关系」时快速翻看。

## 三、演示场景示例（分步操作剧本）

> 场景设定：海信容声（广东）冰箱有限公司标准化工程师「张工」的日常——**每天早上打开平台，先跑一次「每日采集预警」合并报告**，看看最近一天行业里发生了什么、哪些要提前准备；再关注标委会换届机会、看竞争对手在冰箱保鲜标准上的布局。

### 步骤 0 · 平台总览（约 20 秒）

- **操作**：打开 `http://127.0.0.1:5277`，展示顶部导航 5 个页签（每日采集预警 / 标准采集 / 标准预警 / 竞争分析 / 组织动态）和右上角「收件人管理」入口。
- **讲解**：这是海信标准情报平台。本次演示聚焦功能模块二「标准公告与标准组织」。注意第一个页签「每日采集预警」——它就是标准采集和标准预警的**合并快捷入口**，日常定期收集就靠它；后面两个页签（标准采集、标准预警）是拆开用的单功能版。

### 步骤 1 · 每日采集预警合并报告（★ 重点，对应需求二-①+②，约 60 秒）

- **操作**：切到「每日采集预警」页签 → 「报告日期」默认显示最近一天（Asia/Shanghai 时区，可调整为任意历史日期补采）→ 关键词默认六词（冰箱/保鲜/食品保鲜/制冷/家用电器/家电）→ 类型保持四类全选 → 相关度阈值 80、预警节点 90 → 点「**生成报告**」。
- **预期界面**：进度面板出现「任务创建 → 检索 → LLM 提取 → 处理 → LLM 报告 → 完成」日志流；随后「报告预览」区出现**两份 Markdown 报告卡片**：
  1. **标准采集报告**：待办提醒（最近一天检索命中 N 条 / 相关度≥80 有 M 条 / 最近一天新发布公告 X 条）、采集明细表、按类型与计划形式统计、采集日志、行动建议；
  2. **新国标预警推送报告**：监测概况、即将实施标准列表（标准号/标题/实施日期/距实施天数/预警节点）、分角色差异化推送文案（张工·标准化 / 王工·研发 / 认证部 / 市场部）、AI 解读。
- **讲解要点**：
  - **这就是「定期收集 + 固定检索最近一天」**：报告日期默认取最近一天（Asia/Shanghai 时区），每天跑一次即完成当日收集归档；如某天漏采，可在「报告日期」里补选历史日期回采；
  - **两份报告一份数据**：同一批最近一天数据同时做采集规范化/相关度打分 和 预警标记，一次执行、两份产出；
  - **数字由代码算、LLM 只写叙述**：命中条数、提醒条数、距实施天数等统计全部由代码精确计算，大模型只生成标题、摘要、行动建议、分角色推送文案——防止模型自行重算导致数字失真（这是 UI 看不出来的关键口径，评委很可能追问）；
  - 若评委追问「怎么推送」，点底部「审批通过并推送邮箱」演示审批 → 推送链路（SMTP 已配置时）。

### 步骤 2 · （可选）拆分版标准采集 / 标准预警（对应需求二-①②的单独使用，约 30 秒）

> **仅在评委追问「能不能单独看采集 / 只看预警」时演示**，平时跳过。

- **操作 A（采集）**：切到「标准采集」页签 → 关键词/数据源/阈值 → 点「开始采集」→ 展示结果表（标准号/标题/文号/发文机关/日期/摘要标签/相关度徽标）与采集日志。
- **操作 B（预警）**：切到「标准预警」页签 → 关键词 + 类型（国标/计划）→ 预警节点 90 → 点「开始监测」→ 展示预警列表（距实施天数 + ≤90/30/7 徽标）与即将实施列表。
- **讲解要点**：采集/预警就是从「每日采集预警」拆出来的单功能版——想自定义检索日期窗口（每日采集预警默认最近一天）、或只想要其中一份结果时，用这两个页签；日常例行就一个「生成报告」搞定。

### 步骤 3 · 组织动态（对应需求二-③，约 40 秒）

- **操作**：切到「组织动态」页签 → 关键词「冰箱/家电/家用电器/制冷」→ 通知类型勾选「征集委员/征集意见公示」→ 提醒天数 15 → 专家匹配权重保持 30/20/30/20 → 点「**开始采集与推荐**」。
- **预期界面**：通知列表出现「SAC/TC46 全国家用电器标准化技术委员会换届及征集委员」通知（可能带黄色「演示」徽标）→ 下方专家匹配推荐表（匹配度/姓名/部门/职称/专业领域/标准经历/匹配原因/建议「推荐」或「备选」）→ 待办跟踪（截止倒计时 + 提前 15/3 天提醒节点）。
- **讲解要点**：
  - 系统自动从**企业内部专家库**（`expert-db.mjs`，生产可对接 HR 系统）匹配委员候选人，四个维度加权打分、匹配原因可溯源，可一键导出委员推荐表（CSV）；
  - **关键解释（UI 看不出来）**：如果当期实时数据与家电关键词零命中，系统会注入一条 SAC/TC46「受控演示通知」并打上「演示」标记——这是按《需求改造》「采集广度可用受控演示数据代替，来源/解析/匹配逻辑不缺失」的原则做的，**保证专家推荐闭环任何时候都能演示**，不是造假数据（详见 §五-6）。

### 步骤 4 · 竞争分析（对应需求二-④，约 60 秒）

- **操作**：切到「竞争分析」页签 → 关键词默认六词 → 类型全选 → 日期选「近5年」→ 主导判定「起草单位首位」→ 企业集团表（海信系/美的/海尔/格力/美菱，可增删）→ 点「**开始实时分析**」→ 可选勾选「调试模式」展示全链路诊断。
- **预期界面**：进度流（检索→领域过滤→起草单位补抓→详情补抓→LLM 提取→合并→分析结论）→ 顶部 4 张统计卡（标准总数/海信参与/保鲜技术占比/覆盖省份）→ 四张图（柱状图、饼图、折线图、中国地图热力图）→ AI 智能分析结论 3 条（竞争格局/趋势洞察/机会识别）→ 点击柱体弹出该企业标准明细下钻弹窗 →「导出Excel / 导出PDF报告」。
- **讲解要点**：
  - 这就是需求里说的**类似专利对比分析**：录入起草单位关键词，系统自动匹配海信系等企业集团，统计其主导/参与起草的标准情况；
  - 「主导」判定口径可选首位/前3位，直接影响统计数字（演示时提一句口径可切换）；
  - 行业标准（QB/T 等）起草单位在 SAMR 不公开，系统会走 hbba 备案库 best-effort 补抓，补不到的明细里明确显示「暂无公开起草单位数据」，**不编造**（§五-5）。

### 步骤 5 · 收尾（约 15 秒）

- **操作**：回到「每日采集预警」或任一模块底部「审批通过并推送邮箱」，展示审批确认 → 收件人预览 → 推送成功提示（若 SMTP 已配置）。
- **讲解**：每个业务模块跑完都可走「审批 → 推送」闭环，把采集结果、预警信息、推荐名单精准推给相关同事。

## 五、UI 看不出来的关键逻辑与疑难解释（评委 Q&A 预案）

> 以下每条都是「界面上看不出来、但评委很可能追问或产生误解」的点，务必在演示前吃透，被问到时能脱口而出。

### 1. 「每日采集预警」和「标准采集 / 标准预警」是什么关系？
- **每日采集预警是合并快捷入口**：作用 = 每天定期收集 + 固定检索最近一天。一次执行同时产出采集报告 + 预警推送报告两份产出，是日常例行使用的入口。
- **标准采集 / 标准预警是拆出来的单功能版**：需要自定义检索窗口（每日采集预警默认最近一天）、或只想看采集、或只想看预警时使用。
- 三个模块共享同一套底层爬虫（`crawl-samr.mjs`）与 LLM 提取，只是「筛选口径 + 产出形态」不同。

### 2. 「数据是真的吗？还是 mock？」
- 真实爬取。`crawl-samr.mjs` 直接调用 std.samr.gov.cn 官方高级检索 JSON 接口（与网站前端同一接口，GET 无需登录），列表/详情/起草单位均来自真实返回；所有标准号、标题都带原文链接，点击可到官网核验。
- 若 LLM 未配置，页面顶部会显示「LLM 未配置」，此时结构化提取降级为「官方字段 + 详情页显式键值」，**不会伪造 AI 标签和结论**（无结论时不编）。

### 3. 每日采集预警报告里的数字为什么「由代码算、不让 LLM 算」？
- 检索命中的记录可能包含**在审国家标准计划**（计划记录无发布日期），因此报告严格区分「最近一天检索命中 N 条」与「最近一天新发布标准公告 X 条」。
- 这类统计、天数、分级全部由代码按真实数据精确计算（`computeAlertFlags`、`scoreRelevance` 等确定性函数），LLM 只生成标题、摘要、行动建议、分角色推送文案与 AI 解读——**防止模型自行重算导致数字失真**。

### 4. 相关度分数（80 分提醒）是怎么算的？
- 公式（满分 100）：**标题命中关键词 ×30 + 范围/摘要/标签命中 ×10 + ICS/CCS 分类命中白名单 ×40**。
- 阈值默认 80，可在采集页/每日采集预警配置。≥阈值 → 蓝色「✓」提醒；0<得分<80 → 黄色「⚠」；0 分不显示徽标。

### 5. 竞争分析里有些行业标准（QB/T 等）没有起草单位？
- SAMR 对部分行业标准不公开起草单位，系统会从 `hbba.sacinfo.org.cn` 备案库 **best-effort 补抓**；补不到的明细行明确显示「暂无公开起草单位数据」，**LLM 不得臆造**。统计口径里这部分会如实标注。

### 6. 组织动态的「演示」徽标是什么？会不会被当成造假？
- 当实时数据与关键词**零命中**（比如当期没有家电标委会换届通知）时，系统注入一条 **SAC/TC46 受控演示通知**并打「演示」标记（`isDemo: true`，来源标注「受控演示场景」）。
- 这是依据需求改造「采集广度可用受控演示数据代替，但来源、条件解析、专家匹配逻辑不缺失」的原则设计，**保证演示闭环任何时候都能跑通**；而专家匹配打分用的是真实算法（职称/年限/标准经历/专业领域加权，匹配原因可溯源），不是预先写死的假结果。

### 7. 专家匹配的分数怎么来的？
- 四维加权（默认 30/20/30/20，页面可调）：职称达标满分、不达标按 40%；工作年限按比例；标准经历按「主导≥3 项满分 / 2 项 92% / 1 项 85% / 仅参与 72%」梯度；专业领域按通知征集范围与专家领域覆盖比例。每条匹配输出 `score + breakdown + reasons`（分数构成 + 匹配原因），点击可看为什么推荐这个人。

### 8. 竞争分析里「主导」和「参与」的口径？
- 「主导」= 起草单位列表命中企业关键词的位置：**首位**（第一个起草单位命中）或 **前 3 位**（前三个里任一击中即算），页面下拉框可切换，切换后统计随之变化——口径不同数字不同，这是可配置的业务口径，不是 bug。

### 9. 计划↔发布合并是什么？
- 同一标准可能同时存在于「国家标准计划库」和「已发布标准库」（一条计划、一条发布），统计前必须合并去重、优先保留已发布版，只补计划号/制修订信息，**避免同一标准被重复计数**。

### 10. 邮件推送的安全设计？
- 「审批 → 推送」两步走：先记录审批人/时间，再由服务端强制**收件人白名单 + 发送限频**（会话 60 秒 3 封 / IP 1 小时 12 封 / 全服务 24 小时 50 封），禁止成为开放邮件转发器；SMTP 凭据只走 `.env.smtp.local`（权限 600）或部署平台 Secret，**不进前端、不进 Git、不进日志**。

### 11. 时区口径（每日采集预警报告）？
- 「最近一天」固定按 **Asia/Shanghai** 时区计算（避免服务器时区差异导致报告日期错位）；页面「报告日期」直接显示当次检索的日期，可修改补采历史日期。

### 12. 需求里说的「对接工信部」在哪？
- 主数据源当前为**全国标准信息公共服务平台（国家市场监管总局）**，已覆盖国标/行标/地标/计划四类真实数据；**工信部标准平台（std.miit.gov.cn）**已完成可达性验证、定位了公开查询接口路径（`/kjsStandproject/`），规划为二期接入，用于进一步补全行业标准起草单位等信息——架构上已预留扩展位。
