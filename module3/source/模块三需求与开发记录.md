# 模块三：法律法规展示及政策解读

> 项目状态：任务一到任务二流转已接通；标题／内容 JSON 预处理、自动模型分类和人工调整已实现
> 建立日期：2026-08-14  
> 使用对象：标准化工程师、政策研究人员

## 一、原始需求

### 1. 政策收集

支持录入关键词、主要网站等信息，自动收集相关政策；支持实时或按周收集。

### 2. 实时／定期更新

依据海信对外部网站的访问策略，对关注的信息进行实时或定期更新。

### 3. 分级、分类管理

将收集到的产业相关政策按照两个维度展示并支持检索，例如：

- 国家／地区
- 通用政策／产业专用政策

### 4. 政策解读

聚焦与产业、行业相关性强的政策；明确各类政策的解读主体，尤其是共性政策的解读，降低因解读偏差造成不良后果的风险。

### 5. 精准推送

根据配置的政策管理主体，将相关政策信息精准推送给关注人员。

## 二、第一性原理需求分析

### 核心结论

模块三表面上是“政策收集、展示、解读和推送”，真正需要解决的问题是：**如何把分散、持续变化的外部政策，可靠地转化为企业内部可验证、可分派、可追踪的行动。**

因此，产品的核心价值不在于收集了多少文件，也不只是生成一段 AI 摘要，而在于让用户快速回答五个问题：

1. 发生了什么变化？
2. 为什么与本企业、产品或地区有关？
3. 这个判断依据原文中的哪些条款？
4. 谁应当在什么时间采取什么行动？
5. 信息是否已被正确的人确认和处理？

### 核心用户

- **政策研究人员**：维护关注范围和政策来源，筛选政策，形成初步解读并跟踪政策变化。
- **标准化工程师／业务专家**：判断政策对产品、技术标准和具体业务的影响，复核专业解读。
- **政策管理主体**：配置分类、责任人和推送规则，审批重要解读，确认责任归属。
- **关注人员／业务负责人**：接收与自己相关的政策，理解影响，确认知悉并执行后续行动。
- **法务、合规或指定专家**：在高风险政策上进行最终人工复核；该角色是否独立设置，后续需结合企业流程确认。

### 用户必须完成的关键任务

1. 定义“我们关注什么”，包括地区、产业、产品、企业主体、关键词和政策来源。
2. 从可信来源发现新增、修订、废止或即将生效的政策，并识别重复文件和版本变化。
3. 判断政策是否与海信相关，以及具体影响哪些主体、产品、地区或业务环节。
4. 基于政策原文生成结构化解读，并能从每项结论回到对应条款和官方来源。
5. 将影响转化为明确的风险、机会、待办事项、责任人和时间要求。
6. 把不同政策精准分派给对应管理主体和关注人员，而不是无差别群发。
7. 跟踪送达、阅读、反馈、复核和处理状态，形成可审计记录。

### 当前业务中的根本问题

- **信息分散**：政策存在于不同国家、地区和主管机构网站，更新节奏不一致，容易漏看。
- **信息过载**：大量文件与具体业务无关，人工筛选成本高，简单关键词匹配又容易误报。
- **变化难辨认**：发布、修订、生效、废止等状态容易混淆；同一政策的不同版本可能导致错误判断。
- **解读不一致**：同一政策由不同人员解读时可能产生差异，AI 直接给结论又存在幻觉和越权风险。
- **影响难落地**：摘要说明了“政策讲什么”，却没有回答“海信哪部分业务该做什么”。
- **责任链断裂**：政策被推送不等于被处理；缺少责任主体、确认状态和后续行动的闭环。

这些问题说明，“政策列表 + AI 摘要”只能解决阅读效率，不能满足企业对可靠性、责任和执行的真实要求。

### 不可缺少的最小闭环

```text
可信来源发现政策
    → 校验来源、状态、版本并去重
    → 结合企业关注画像判断相关性
    → AI 生成带原文依据的解读初稿
    → 对应领域人员审核或修正
    → 形成影响、行动、责任人与期限
    → 精准推送给相关人员
    → 跟踪确认与处理状态
```

黑客松第一版不必连接所有政策网站，但必须用至少一条政策完整证明上述闭环。采集广度可以用受控演示数据代替，来源、解读依据、人工复核和责任追踪不能在产品逻辑中消失。

### 核心信息对象

- **政策原件**：标题、文号、发布机关、发布日期、生效日期、地区、政策状态、版本、官方链接和原文。
- **企业关注画像**：企业主体、产业、产品、技术领域、经营地区、关键词和责任部门。
- **政策解读**：政策摘要、适用对象、关键变化、相关条款、影响、风险／机会、置信度和待确认项。
- **审核记录**：AI 生成状态、解读主体、审核人、审核意见、版本和时间。
- **推送与行动**：接收人、推送原因、阅读状态、反馈、责任人、期限和处理状态。

### 可信度与风险边界

- **官方原文优先**：第三方转载只能作为线索，正式解读必须保留官方来源。
- **事实与判断分层**：原文事实、AI 摘要、影响推断和人工结论必须明确区分。
- **结论必须可追溯**：重要解读应引用具体条款，用户可以直接回看上下文。
- **版本和时效可见**：必须显示发布、生效、失效或修订状态，避免使用过期政策。
- **AI 不充当最终法律责任主体**：AI 负责筛选、提取和生成初稿；高风险或共性政策由指定人员审核后才能正式推送。
- **展示不确定性**：证据不足或存在歧义时，应显示待确认项，而不是生成确定性结论。
- **过程可审计**：保留来源、生成、修改、审核、推送和确认记录。
- **访问策略受控**：采集频率和方式须服从企业外网访问策略，实时更新不是默认承诺。

### 第一版验证标准

第一版产品应让评委通过一条示例政策清楚看到：

- 系统知道政策从哪里来、当前是否有效；
- 系统能说明政策为何与某一企业主体或业务相关；
- AI 解读中的关键判断能够定位到原文依据；
- 用户能够审核解读并确定责任人与处理要求；
- 系统能够把政策送给正确的人，并展示确认／处理状态。

## 三、参考项目检查

### 参考项目

### 现有能力与流程

参考项目是一个基于 Python Tkinter 的桌面工具，可通过 PyInstaller 打包为 Windows EXE，并非网页系统。用户在一个纵向配置界面中完成以下操作：

1. 选择最近一周、最近一个月或自定义日期范围。
2. 选择国家级、预设区域、全国或自定义省份。
3. 配置最大爬取页数。
4. 选择 Gemini、Kimi 或智谱模型并填写 API Key。
5. 选择约 300 字的快报版或约 500 字的深度版。
6. 启动“爬取 → 正文提取 → AI 总结 → Markdown 报告生成”任务。
7. 查看阶段进度、实时日志，必要时终止任务，完成后打开报告。

### 技术结构

| 部分 | 参考项目实现 | 作用 |
| --- | --- | --- |
| 用户界面 | Python Tkinter / tkcalendar | 参数配置、进度和日志展示 |
| 政策发现 | requests + BeautifulSoup | 从北极星售电网政策列表抓取标题、链接和列表日期 |
| 分类筛选 | 标题关键词 + 省份名称匹配 | 粗略判断国家级或所属省份 |
| 正文提取 | 固定 CSS 选择器 + Body 降级方案 | 提取标题、日期和文章正文 |
| AI 处理 | Gemini / Kimi / 智谱适配器 | 按模板生成快报或深度摘要，失败时重试或切换模型名 |
| 输出 | 本地 Markdown 文件 | 按省份分组生成月度政策摘要报告 |
| 任务反馈 | 后台线程 + 四阶段进度 +日志 | 避免界面阻塞并反馈长任务状态 |

关键实现文件：

- `核心程序/policy_tool_gui_final.py`：界面、配置、任务编排与报告生成。
- `核心程序/improved_crawler.py`：政策列表抓取、日期与省份过滤。
- `核心程序/content_extractor.py`：正文抽取与清洗。
- `核心程序/unified_ai_summarizer.py`：多模型调用、重试和报告格式化。
- `核心程序/prompt_templates.py`：快报、深度、结构化等提示词模板。
- `输出报告/*.md`：真实运行生成的政策月报样例。

### 值得借鉴的设计

- **先筛选再处理**：日期、地区和关注范围是降低信息噪声的必要入口。
- **任务阶段透明**：把长任务拆成采集、提取、AI 分析和输出阶段，并展示进度、日志和失败信息。
- **快报／深度双层阅读**：同一政策可提供快速浏览和深入研究两种信息密度。
- **采集、提取、AI 分析分层**：能力模块相互隔离，便于后续更换来源或模型。
- **模型适配层**：统一调用接口和失败重试思路可避免界面逻辑绑定单一模型。
- **自定义关注范围**：预设区域与自选地区并存，适合扩展为企业关注画像。

以上仅借鉴产品和架构思路，不直接复制其桌面端代码。

### 不应照搬的部分

- **来源可信度不足**：当前只抓取北极星售电网这一第三方聚合站，不满足企业政策解读对官方原文优先的要求。
- **分类方法过于粗糙**：通过标题是否包含省份或部委关键词分类，容易误判、漏判，无法表达发布机关、适用地区和产业分类等独立维度。
- **缺少政策身份与版本管理**：没有文号、效力状态、修订／废止关系、去重标识和版本链。
- **正文可能不完整**：提示词只使用最多 3000 个字符，长政策的关键条款可能被截断。
- **AI 输出不可验证**：摘要没有条款引用、置信度、待确认项或事实／推断分层。
- **样例存在时间一致性风险**：2026 年 3 月范围的样例报告中出现“2023 年”和“2026 年 4 月”的发布表述，说明列表日期、正文日期和模型输出之间缺少校验。
- **报告丢失关键证据**：抓取阶段保存了 URL，但最终月报只输出摘要正文，用户无法从结论直接回到来源。
- **没有企业相关性分析**：仅按地区筛选，没有企业主体、产品、产业、技术领域或业务环节画像。
- **没有人工审核与责任闭环**：缺少解读主体、审核版本、责任人、精准推送、阅读确认和处理状态。
- **没有系统化数据层**：无数据库、账户权限、审计记录、定时任务和历史政策检索，运行结果只是本地报告。
- **密钥管理不合格**：配置文件使用 Base64 编码而非安全加密；测试函数中还存在硬编码 API Key。新项目不得复制该密钥，原密钥若仍有效应尽快撤销。
- **缺少自动化验证**：未发现正式测试套件，爬虫选择器、提示词输出和日期准确性缺少回归保障。

### 对模块三的启发

参考项目证明了“自动采集 + AI 摘要 + 报告输出”可以作为底层处理管线，但它只覆盖了最小闭环的前半段。模块三网页应在其基础上补齐：

```text
可配置关注范围
→ 多来源政策进入待处理箱
→ 来源／版本／相关性校验
→ 带原文证据的分层解读
→ 人工审核
→ 责任分派与精准推送
→ 确认和处理追踪
```

下一步设计页面时，可以保留“筛选条件、处理进度、快报／深度阅读”三个优点，但页面中心应从“一次性任务参数配置”转向“政策待办与处理闭环”。

## 四、产品范围

### MVP 范围

当前页面改为四个独立任务板块，通过顶部入口切换各自工作页：

1. 政策发现与更新：合并原步骤一、二，负责检索政策以及决定单次或定时执行。
2. 政策分类标注：承接采集结果，逐条标注国家／地方层级和通用／产业类型。
3. 政策分析与解读：选择已分类的特定政策，再选择“专家解读型”或“条款拆解型”，分别路由至对应 Skill 生成并复核报告。
4. 邮件定向推送：将审核后的政策解读发送给指定人员并跟踪发送状态。

任务一保留现有真实采集能力，并支持用户多选有用政策、批量确认后自动进入任务二。进入任务二时，系统自动拆解标题并生成内容摘要 JSON，随后调用可配置的大模型判断政策层级和适用类型；模型结论仅供参考，用户可以自定义调整。任务三已完成分析类型与本地 Skill 的前端映射，但真实 Skill 调用、报告持久化和邮件推送仍未接入。

## 五、页面与交互

### 信息架构

当前页面使用四个顶部任务入口，各页面之间形成明确的输入／输出关系：

```text
任务一：政策发现与更新（步骤 01—02）
    ↓ 产出已采集政策
任务二：政策分类标注（步骤 03）
    ↓ 产出带层级与类型标签的政策
任务三：政策分析与解读（步骤 04）
    ↓ 选择专家解读型／条款拆解型并产出审核后的分析报告
任务四：邮件定向推送（步骤 05）
    ↓ 产出发送记录与接收状态
```

### 核心页面

页面顶部使用四张紧凑任务卡作为一级导航，点击后只展示当前任务工作页。任务一沿用参考工具的纵向配置、操作和进度结构；任务二至四使用独立工作页说明输入、任务和输出边界。桌面端四列，窄屏为两列。

### 核心交互

1. 可填写关注关键词，并通过常用关键词按钮补充内容。
2. 可选择最近 7 天、最近 30 天、最近 1 年或自定义政策发布日期范围；该范围不等同于政策生效日期。
3. 点击主要网站框可打开大尺寸网站列表，查看网站名称与链接并进行多选。
4. 网站列表底部可新增自定义网站；填写名称和链接后，新网站自动加入列表并被选中。
5. 已选网站与关键词关联；点击开始处理时会校验关键词和网站选择，并显示当前检索范围。
6. 选择定期更新后可展开定时任务设置，配置每天／每周／每月、执行日期和具体时间。
7. 保存定时任务后，定期更新卡片会同步显示新的执行计划。
8. 地区层级使用与主要网站一致的弹出列表，默认提供国家级和广东省，并支持多选。
9. 地区框及下方说明会同步展示当前选中的地区范围。
10. 可选择通用／产业专用政策分类。
11. 可在速览版／深度版间切换，并选择负责复核的解读主体。
12. 可多选默认关注人员。
13. 点击开始处理后校验关键词、来源和政策发布日期范围；工信部来源会执行真实分页查询并在日志中展示每个关键词的命中数。
14. 采集结果按官方发布时间倒序展示，点击标题可回到工信部原文；停止按钮可中断当前请求。
15. 当前没有真实定时任务、AI 解读、数据保存或外部推送；其他网站尚未配置来源适配器。
16. 任务一采集结果支持逐条选择、全选、取消选择，并实时显示已选数量。
17. 用户点击“确认并进入分类标注”后，已选政策追加到任务二并自动切换页面；重复确认不会产生重复政策。
18. 任务二按一行一条显示政策；流转后自动执行“标题拆解 JSON → 内容摘要 JSON → 大模型分类”，无需用户点击运行。
19. 模型输出政策层级、适用类型、置信度、判断说明和证据；用户可以点击“自定义调整”覆盖模型建议。
20. 未配置模型时仍完成结构化 JSON，并明确提示在 `.env.local` 填写 Base URL、模型名和 API Key，不生成伪模型结论。

### 第一版演示故事线

用户先从顶部判断当前要完成哪一类任务，再进入对应工作页；任务一完成采集后，结果才流向分类、解读和邮件推送，而不是在同一张长表单里一次性配置所有步骤。

## 六、技术方案

### 技术栈

- React 19 + TypeScript 7：组件化实现单页政策工作台。
- Vite 8：本地开发与生产构建。
- Lucide React：使用统一的线性功能图标，避免 emoji 作为界面控件。
- 原生 CSS：建立企业级视觉变量、响应式布局和组件状态，不引入额外 UI 框架。
- Vite 本地中间件提供工信部真实采集接口；结果仍仅使用前端内存状态，无数据库。

### 数据模型

当前只维护页面配置状态，包括关键词、政策来源、更新频率、地区、分类、解读版本、解读主体和推送对象，不定义正式政策业务数据模型。

### AI 能力

未开发。

### 第一版实现文件

- `package.json`：前端依赖与开发、构建、预览脚本。
- `src/App.tsx`：五个纵向配置区块、表单控件、模式按钮及演示进度逻辑。
- `src/styles.css`：页面视觉系统、桌面布局与响应式规则。
- `src/main.tsx`：React 应用入口。
- `vite.config.ts`：Vite 本地服务配置，默认端口 5173。
- `index.html`：网页入口和基础元信息。

### 已实现的 UI 与本地交互

- 参考工具式深色居中标题栏和纵向配置页面。
- 政策收集：关键词输入、常用关键词按钮和主要网站选择。
- 主要网站选择器：约 660px 宽的弹出窗口、网站名称与链接、官方／自定义标记、复选框多选和已选数量。
- 新增网站：名称与链接输入、必填及链接格式校验、确认后新增并自动选中。
- 关键词关联：主要网站框下显示当前选中数量和将要检索的关键词。
- 自定义定时任务：点击定期更新卡片后展开设置，可选择每天／每周／每月。
- 每周任务支持多选星期；每月任务支持选择 1 至 28 日；所有任务均可设置执行时间。
- 保存后卡片摘要同步更新，并保留“仅为前端配置”的能力边界提示。
- 地区层级：沿用主要网站选择器的触发框、标签、较大弹窗、复选框列表和已选数量提示。
- 地区选项逐行展示名称及适用范围说明，至少保留一个选项，支持多个地区同时关注。
- 列表不提供笼统的“其他地区”；底部使用“新增地区”入口，由用户填写具体地区名称。
- 新增地区包含必填和重复名称校验，确认后新增一行并自动选中。
- 国家级、广东省及预置官方网站属于系统项，不显示删除按钮。

- 实时／定期更新：实时更新与每周更新模式按钮。
- 分级分类管理：地区下拉框、通用／产业专用分段按钮和当前选择说明。
- 政策解读：速览版／深度版大按钮及解读主体选择。
- 精准推送：三类关注人员多选按钮和推送逻辑说明。
- 底部开始处理、停止按钮和处理进度展示。
- 工信部来源适配器：动态解析搜索分类 ID，按关键词分别查询并去重，支持分页、超时、重试、限速和中断。
- 本次真实采集结果：展示官方标题、发布日期、发布机构、文号、政策类型、主题、正文摘要、附件数量和原文链接。
- 政策筛选与流转：采集结果支持多选及批量确认，确认后跨任务流转到分类标注页。
- 分类标注列表：一行一条政策，左侧展示政策证据，右侧自动显示模型结论，并支持展开标题／摘要 JSON 和人工调整。
- 模型适配器：兼容 OpenAI Chat Completions 协议，通过后端读取环境变量，API Key 不进入浏览器和 Git。
- 精准推送已移动到处理进度之后，表达“完成政策分析后再选择推送人员”的业务顺序。
- 开始处理操作区由深蓝色改为浅青灰色，使用青绿色左侧强调线，保留绿色开始与浅红停止按钮。
- 处理进度下方新增实时日志，逐条展示时间、级别、处理阶段和具体信息。
- 日志区支持信息、成功、警告和错误四种视觉状态，错误会明确标出发生阶段。
- 配置校验失败、开始处理、接口未接入和用户停止操作均会写入日志；新日志自动滚动到底部。
- 提供清空日志按钮，为后续接入网站访问、正文解析和 AI 解读错误预留统一反馈位置。
- 实时日志背景使用白色与浅绿色，标题图标改为浅绿色，保持与页面主色系一致。

- 完成全页字号与留白优化：放大步骤标识、区块标题、字段标题、卡片正文和辅助说明，提升远距离浏览时的可读性。
- 收紧更新方式、政策解读、推送对象等选择卡片的最小高度和内边距，减少无效留白并保留清晰点击区域。

- 在紧凑版基础上适度恢复呼吸感：增加区块间距、标题区与内容区内边距以及卡片文字周围留白。
- 统一主要面板为 11px 圆角和轻柔投影，使白色功能区在浅灰背景上更有层次，同时避免厚重悬浮感。
