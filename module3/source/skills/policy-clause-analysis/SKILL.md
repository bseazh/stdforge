# 政策条款拆解技能

将政策文件逐条拆解为面向白电/小家电行业企业的合规指南。

## 适用场景

当用户需要逐条解读政策原文条款，并生成面向家电行业的合规指南时使用此技能。

典型触发场景：
- 用户提供政策文件链接或原文，要求进行条款拆解
- 用户需要逐条核对合规要求
- 用户需要生成条款拆解报告、合规清单

## 拆解框架

### 标准结构

政策条款拆解报告应包含以下三个部分：

```
【开头】政策概览（简化版）
一、政策背景（精简版，3-5句话）
二、核心内容框架（表格说明整体结构）

【主体】条款逐条拆解
三、条款解读
   （一）第一条：条款名称
       原文摘要
       解读说明
       合规要点
       注意事项

   （二）第二条：条款名称
       原文摘要
       解读说明
       合规要点
       注意事项

   ...依此类推...

【结尾】行动指南
四、企业合规清单
   - 按条款整理的合规要求清单
   - 时间节点
   - 责任部门建议

五、风险提示
   - 容易理解偏差的条款
   - 模糊地带
   - 常见误读
```

### 条款拆解模板

每条条款的拆解应包含以下四个要素：

```
### （X）条款名称

**原文摘要：**
> 政策原文的关键语句

**解读说明：**
这条条款是什么意思，背景是什么，为什么这么规定

**合规要点：**
企业应该做什么（正面要求）

**注意事项：**
不应该做什么，容易做错什么，风险提示
```

### 条款分级解读

不是每条条款都需要同等深度的解读，建议分级：

| 条款类型 | 解读深度 | 示例 |
|---|---|---|
| 核心条款 | 详细解读（原文+解读+合规要点+注意事项） | 管控物质、限量要求、合格评定 |
| 重要条款 | 中等解读（原文+解读+合规要点） | 标识要求、过渡期安排 |
| 一般条款 | 简略解读（原文+简要说明） | 定义、术语、附则 |

### 合规清单模板

```
### 按条款整理的合规要求

| 条款 | 合规要求 | 责任部门 | 完成时限 |
|---|---|---|---|
| 条款1 | 具体要求 | 部门名称 | 时间节点 |
| 条款2 | 具体要求 | 部门名称 | 时间节点 |

### 时间节点

| 时间节点 | 事项 |
|---|---|
| 即刻起 | 事项1 |
| 1个月内 | 事项2 |
| 3个月内 | 事项3 |
```

## 文风要求

### 结构性要求

- 使用"一是...二是...三是..."的排比结构陈述解读说明
- 关键信息使用加粗标注
- 时间节点和合规要求使用表格呈现
- 原文摘要使用引用格式（>）

### 语言风格

- 正式、严谨，但不晦涩
- 参考工信部官方解读的语气和措辞
- 使用《政策名称》简称，避免重复全称
- 避免口语化表达

### 格式规范

- 标题层级：一级标题（一、二、三...）、二级标题（（一）（二）（三）...）
- 关键术语首次出现时使用全称，后续使用简称
- 重要时间节点单独列表
- 风险提示分条陈述

## 工作流程

### 步骤一：获取政策原文

1. 如果用户提供链接，使用 network-search skill 读取政策原文
2. 如果用户提供原文，直接使用
3. 确保获取完整的政策文件内容

### 步骤二：分析政策结构

1. 识别政策类型：新规、修订、指南、目录、办法等
2. 提取关键信息：发布部门、发布日期、生效日期、过渡期
3. 梳理核心条款和要求
4. 对条款进行分级（核心条款、重要条款、一般条款）

### 步骤三：逐条拆解

1. 按照标准结构逐条拆解每条条款
2. 提取原文摘要
3. 编写解读说明
4. 整理合规要点
5. 补充注意事项

### 步骤四：生成拆解报告

1. 按照标准结构组织内容
2. 参考文风要求调整措辞
3. 确保每条条款都有实质内容
4. 生成合规清单和时间节点

### 步骤五：质量检查

1. 检查是否遗漏重要条款
2. 检查每条条款的解读是否准确
3. 检查合规清单是否完整
4. 检查风险提示是否全面

## 输出格式

拆解报告应以 Markdown 格式输出，包含：

- 报告标题
- 解读类型、适用行业、政策发布日期、解读日期
- 三个标准部分（政策概览、条款拆解、行动指南）
- 解读依据（引用的法规和文件）
- 免责声明

## 注意事项

- 本技能生成的拆解仅供参考，不构成法律意见
- 具体合规要求请以主管部门发布的正式文件为准
- 对于模糊条款，建议企业向主管部门或行业协会确认
