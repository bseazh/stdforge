# 模块三：法律法规与政策解读测试案例（Demo 验收版）

对应需求：三-①、三-②、三-③、三-④、三-⑤

## Demo 验收范围

- 政策来源以工业和信息化部政策文件库为真实采集示例；其他网站保留配置入口，不作为本轮真实爬虫验收项。
- “实时更新”指用户触发后立即执行一轮真实网站检查，并显示进度、日志和结果；持续轮询与后台定时任务不属于本轮验收范围。
- 定时更新保留周期和时间配置 UI，待实时检查稳定后再接入后台任务调度。
- 政策解读使用项目内置的专家解读型或条款拆解型 Skill。
- 精准推送以服务端 SMTP 邮件为验收渠道。

## 案例9：政策实时采集与自动分类

对应需求：三-①、三-②、三-③  
角色：政策研究人员 赵博士

### 【前置条件】

1. 模块三服务已经启动，工信部政策文件库可访问。
2. DeepSeek 模型配置有效。
3. 页面已选择工业和信息化部政策文件库作为政策来源。

### 【精确输入】

政策采集配置：

- 更新方式：实时更新
- 政策来源：工业和信息化部政策文件库
- 关键词：冰箱、白色家电
- 发布日期：2020-01-01 至 2026-08-15
- 执行动作：点击“开始实时检查”

采集完成后：

1. 从结果中选择与冰箱或家电行业相关的政策。
2. 点击“确认并进入政策分类”。
3. 在政策分类页分别选择政策层级与适用类型筛选条件。

### 【期望输出】

1. 实时检查状态：

   - 页面进度最终达到 100%。
   - 状态显示“实时检查完成：取得 N 条工信部官方政策”。
   - 实时日志出现“实时更新”阶段，并说明本轮已经直接访问工信部政策文件库。
   - N 取决于工信部实时返回结果，不以固定条数作为通过条件，但必须大于 0。

2. 政策列表：至少包含真实测试中命中的下列政策之一：

| 政策标题 | 官方元数据 | 自动分类参考结果 |
| --- | --- | --- |
| 《工业和信息化部办公厅关于开展2022年度国家工业和信息化领域节能技术装备产品推荐工作的通知》 | 工信厅节函〔2022〕134号、2022-06-23、节能与综合利用司 | 【国家级】【产业政策】 |
| 《五部门关于推动轻工业高质量发展的指导意见》 | 工信部联消费〔2022〕68号、2022-06-17、消费品工业司 | 【国家级】【产业政策】 |
| 《工业和信息化部关于公布2021年工业产品质量控制和技术评价实验室复核结果的通告》 | 工信部科函〔2021〕285号、2021-11-02、科技司 | 【国家级】【通用政策】 |

3. 政策详情包含：

   - 政策标题
   - 发布机构
   - 文号
   - 发布日期
   - 官方原文链接
   - 政策摘要
   - 文件类型与主题
   - 附件数量

4. 自动分类与筛选：

   - 系统自动生成标题与摘要 JSON。
   - DeepSeek 自动给出政策层级、适用类型、置信度、判断理由和证据。
   - 支持按照“政策层级 + 适用类型”组合筛选。
   - 用户可以人工修改模型给出的层级和适用类型，修改后筛选结果立即同步。

### 【开发测试要点】

1. 选择“实时更新”后必须产生真实网络请求，不能只修改页面文案。
2. 真实检查需要记录配置校验、更新方式、政策来源、关键词检索和完成状态。
3. 搜索命中结果必须保留工信部官方链接和官方元数据。
4. 自动分类失败时不能伪造模型结果，应保留结构化 JSON 并允许人工调整。
5. 模型结论为参考项，人工修改后的最终值应作为筛选依据。
6. 其他网站没有接入真实适配器时，应明确提示本轮不会访问，而不是显示虚假采集结果。

### 【演示提示】

先选择“实时更新”，展示按钮变为“开始实时检查”；执行后重点展示 100% 进度、实时更新日志、工信部官方结果，以及政策层级和适用类型的组合筛选与人工修正。

## 案例10：政策分主体精准解读

对应需求：三-④  
角色：政策研究人员 赵博士、业务负责人

### 【前置条件】

1. 《工业和信息化部办公厅关于开展2022年度国家工业和信息化领域节能技术装备产品推荐工作的通知》已经完成采集和分类。
2. 政策完整原文已经从工信部官方详情页补充取得。
3. DeepSeek 模型配置有效。
4. 项目内两个 Skill 文件路径均可读取：

   - `skills/policy-expert-interpretation`
   - `skills/policy-clause-analysis`

### 【精确输入】

在政策分类页点击该政策的“政策分析”，进入任务 3：

- 分析政策：《工业和信息化部办公厅关于开展2022年度国家工业和信息化领域节能技术装备产品推荐工作的通知》
- 分析类型：专家解读型
- 分析主体：业务负责人
- 执行动作：点击“生成分析报告”

对比验证时，可将分析类型切换为“条款拆解型”，将分析主体切换为“法务与合规组”。

### 【期望输出】

1. 专家解读报告：

   - 按专家解读 Skill 生成 Markdown 报告。
   - 报告至少包含政策背景、政策目标、核心内容、行业影响、企业核心要点、行动建议和风险提示。
   - 报告明确标识分析主体为“业务负责人”，重点和行动建议应面向该主体组织。
   - 不得使用 Skill 示例中的占位日期或虚构政策事实。
   - 无法从政策原文确认的信息应标记为待核实。

2. 条款拆解报告：

   - 切换分析类型后，系统调用条款拆解 Skill。
   - 输出政策概览、条款拆解、合规清单和风险提示。
   - 原文摘要、解读说明、合规要点和注意事项应按照条款结构组织。

3. 报告展示与交付：

   - 页面将 Markdown 渲染为标题、列表、表格和引用等可读样式，不直接展示 Markdown 源码符号。
   - 支持复制 Markdown 原文。
   - 支持点击“保存本地”，由用户选择路径保存 `.md` 文件；浏览器不支持路径选择时自动降级下载。
   - 支持点击“推送报告”，将同一份已生成报告传递至任务 4，不需要重新调用 Skill。

### 【开发测试要点】

1. 两张分析类型卡必须分别映射到正确的项目内 Skill，不能依赖项目外部目录。
2. 分析主体必须进入模型上下文；更换主体后重新生成的报告应体现不同关注重点。
3. 模型调用必须包含政策官方元数据和完整正文。
4. 报告生成时需要关闭无必要的长思考模式，避免推理占满输出预算。
5. 报告生成时使用的 Skill、分析主体和生成时间应作为报告快照保留，后续修改页面选项不能错误改写旧报告标识。
6. 复制、保存和推送必须复用同一份 Markdown 原文。

### 【演示提示】

先展示专家解读型报告，再切换条款拆解型说明两种 Skill 的结构差异。重点演示业务负责人这一分析主体如何影响报告重点，以及“保存本地”和“推送报告”两个交付入口。

## 案例11：按推送分组精准发送政策分析报告

对应需求：三-⑤  
角色：业务负责人阿丽塔、政策管理人员

### 【触发场景】

任务 3 已生成《工业和信息化部办公厅关于开展2022年度国家工业和信息化领域节能技术装备产品推荐工作的通知》的专家解读报告，并点击“推送报告”进入任务 4。

### 【前置条件】

1. SMTP 配置通过受保护且被 Git 忽略的本地 Secret 注入。
2. `/api/health` 返回 SMTP 已配置且身份验证通过。
3. 服务端测试收件人白名单只有 1 个邮箱；真实邮箱不写入前端源码、Git、README 或测试日志。
4. 该联系人在页面中归属于“业务负责人”分组。

### 【精确输入】

推送配置：

- 待推送报告：专家解读报告
- 政策层级：国家级
- 适用类型：产业政策
- 分析主体：业务负责人
- 推送分组：仅选择“业务负责人”
- 收件人数：1 人
- 执行动作：点击“推送”
- 首次操作：输入本地 Secret 中单独配置的邮件管理验证码，建立当前浏览器会话授权

### 【期望输出】

1. 发送前预览：

   - 邮件标题：`[政策分析报告] 专家解读报告｜工业和信息化部办公厅关于开展2022年度国家工业和信息化领域节能技术装备产品推荐工作的通知`
   - 正文信息：专家解读报告、国家级、产业政策、面向业务负责人。
   - 附件名称：政策标题加“专家解读报告.md”。

2. 邮件正文：

   - 明确说明这是一份政策分析报告。
   - 展示政策文件、报告类型、政策层级、适用类型和分析主体。
   - 提示完整报告位于 Markdown 附件中。
   - 不在正文中堆叠完整 Markdown 源码。

3. 报告附件：

   - 完整分析报告以 UTF-8 编码的 `.md` 文件发送。
   - 附件内容与任务 3 已生成并缓存的报告一致，不重新调用 Skill。

4. 发送结果：

   - 服务端只向业务负责人分组中的唯一白名单邮箱发送 1 封邮件。
   - 页面显示 SMTP 服务器已经接受 1 封邮件，并显示附件名称。
   - 实际测试邮箱能够收到邮件正文和 Markdown 附件。

### 【开发测试要点】

1. SMTP 账号、授权码、真实测试邮箱和管理验证码不得进入前端、Git 或日志。
2. 首次新增、删除联系人或发送邮件时必须通过管理验证码建立 HttpOnly 会话；当前会话有效期内不重复输入。
3. 服务端只能向白名单邮箱发送，单次最多 10 个邮箱，并实施每小时发送限频，禁止成为开放邮件转发器。
4. 页面取消选择其他分组后，发送接口只能收到业务负责人分组的邮箱集合。
5. 发送前必须校验报告、分组和联系人均不为空。
6. 同一真实测试命令需要写入本地防重复标记，防止误操作造成重复投递。

### 【演示提示】

展示任务 3 点击“推送报告”后，任务 4 自动显示待推送政策和邮件内容预览；只选择“业务负责人”，完成一次推送。最后在测试邮箱中展示结构化正文和 Markdown 附件。
